### Execution and schema boundary

Both conditions used the same selected model, cases, evidence-tool contract, report mode,
and pooled budget policy. Limits remained eight model turns, 24 evidence calls,
240 seconds per turn, and 15 minutes per investigation. Exact host-mediated approvals were
simulated evaluation fixtures, not production authorization.

Each trial used an independent runtime session and isolated temporary workspace.
Within a trial, investigation, host-supplied evidence, readiness, and finalization retained
that session. The response schema was attached only to the final send, after readiness.
Evidence collection was not schema-constrained; semantic report validation and exact evidence
approvals remained authoritative. There was no unconstrained fallback.

All 30 saved trials passed replay integrity and the applicable strict gates. Skill-specific
gates remain explicitly not applicable to the baseline where the protocol permits it.
The baseline had no enabled skills or plugins; only the skilled condition received the RCA
skill bundle. Passing these checks does not prove provider-side constrained decoding or
causal correctness. See the [finalization contract](SCHEMA-FINALIZATION.md).

## Interpretation and review limits

Fifteen trials per condition repeat five selected cases, not fifteen independent incidents.
Case mix, injected faults, model variability, extractor behavior, and unreviewed mechanism
compatibility limit interpretation. Both conditions used schema finalization; there was no
randomized prompt-versus-schema control.

The debug and production snapshots use the same cases but different models, protocols,
budget limits, and cost-consent wording. They are separate observations, not a controlled
model-only comparison. Do not pool their scores or attribute cross-run differences solely
to model selection.
