AUTOMATIC RPI

When an automatic session continues or stops

Research→Plan + critique→Implement→Review
↳ Required work remains within scopeStart a new child task at Research

Continue

The current phase's gates pass and the next action is authorized.

Pause

The agent needs a retained user decision, missing evidence or a safety confirmation.

Stop

The request is complete, the user stops, or repeated attempts cannot make progress.

Follow-ups cover work required by the request. Optional cleanup stays separate.

The wrapper tracks task completion separately from session completion. A new child cannot bypass unresolved gates or missing evidence. If a previous attempt made no progress, the agent needs new evidence or a materially different corrective approach before starting another loop.
RPI HELPERS

Select helpers for the work at hand

Available skill or subagent↓Name or description matches research↓Expertise fits the question and scope↓Primary assistant combines the evidence

You can supply an alternative

A research skill can provide domain criteria. A registered research subagent can investigate an independent question.

  • RPI Researcher writes one evidence file.
  • RPI Planner revises one assigned phase.
  • RPI Review Builder writes one review record.

The assignment does not expand permissions. The primary assistant keeps the decisions.

Research checks the helper's name or description as well as its relevance to the question. It can also run directly without a worker. Planning supports adaptive, never and always delegation; always blocks when a worker cannot be dispatched. Implementation delegates only ready, independent whole phases with nonoverlapping writes. Review uses one selected builder. User-provided helpers must be available in the host and respect the same limits.

Major changes need behavior evidence for the version being delivered. Supported skips for smaller changes are recorded.

Separate editing and testing

The primary assistant changes the source. The tester assesses the frozen version without editing it.

The exact work depends on the requested mode. Read-only review does not authorize edits. Mechanical checks precede independent static review; required behavior assessment covers the frozen candidate. The workflow-contract reference defines the applicable gates.

Behavior testing defaults to simulation. Native execution needs an explicit request and the required safety controls.

#2858 added parent-owned behavior reassessment. The parent is the assistant managing HVE Builder. It may correct and refreeze a candidate within its authorized scope; the tester remains read-only. Repeating an unchanged assessment to obtain a different verdict is prohibited. Partial, Deferred or Blocked execution cannot establish a pass.
