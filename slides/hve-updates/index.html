This chapter covers the four RPI phase skills, the optional RPI Agent that coordinates them, and the helper lanes that work beside each phase. Research writes the research document, planning writes the plan, implementation writes the changes record, and review compares all of it. Each wave can hand its open questions to helper lanes that run in parallel. A search lane runs at low effort; a lane that reads docs or code runs at max.

C# marks codebase evidence and W# an external source. Research starts balanced; set posture=focused or expansive to change it.

The research template puts the summary, findings and alternatives ahead of the detailed Research Record. The excerpt skips a few sections, such as What You May Not Know and Risks and Open Questions. Read the recommendation and its cited evidence together. Each independent question gets its own narrow lane, and the lanes go out in one parallel batch. The parent picks each lane's effort from how it finds the answer: low when a search lists every match, max when it has to read documentation, issues or code paths. A "not found" from a lane below max gets confirmed before it's recorded, and the Research Record lists every lane with its effort. Focused stays inside a bounded task; expansive is for broad questions where the options are still unknown. C1 and W1 are sample identifiers; no snack research ran.

Example records. Critique examines the plan; the changes record documents implementation and its checks.

A missing plan check is a planning gap, not an observed code defect. rpi-plan-critique looks at the plan through four lenses: Coverage, Evidence, Executability and Risk. They run in parallel through RPI Plan Critic when subagents are allowed, or directly in the planning assistant. The planning assistant verifies each candidate and assigns the PC IDs. Execution status (Complete, Partial, Blocked or Not produced) is separate from the Pass, Revise or Blocked verdict. Fixing the findings does not start another critique. The wrapper tracks task completion separately from session completion. A new child cannot bypass unresolved gates or missing evidence. If a previous attempt made no progress, the agent needs new evidence or a materially different approach before starting another loop. The first task runs one critique and one Review by default. Since #2902, every RPI subagent is optional and read-only. RPI Planner is gone, and RPI Review Builder became RPI Reviewer. Since #3238, each phase sends its independent lanes in one parallel batch and picks each lane's effort from the work. Research uses low for a search that lists every match and max for reading. Review uses low for tool checks such as task markers, high for comparing against written requirements, and max for behavior no requirement states. Critique lenses start from their defaults. RPI subagents run on Claude Haiku 5.5. If a model rejects the requested effort, the dispatch retries once at medium. The lane topics are examples; the parent decides how to split the work. Implementation follows the plan and does not use helper lanes.

HVE Builder came first, on July 11 (#2438). The Prompt Builder agent, prompt and instruction were retired on July 26 (#2474). Modes combine

Create, improve and refactor run together by default. Review or validate alone stays read-only.

Checks come first

Local checks pass before the review starts, so the review looks at a finished candidate.

Stop when stuck

Another correction cycle needs a clear purpose and evidence that it will make progress.

Removed on September 18 in #2902: the hve-builder-tester skill, HVE Artifact Tester, freeze, sandbox, fidelity levels and the behavior gate.

#2902 removed lifecycle machinery that had become a source of confusion. A run now scopes the work, captures the baseline for existing targets, authors the candidate, runs non-mutating local checks, runs one review pass and resolves the outcome as Pass, Revise, Deferred or Blocked. rpi-research comes in only for open-ended exploration or a decision-critical evidence gap. Repeated same-cause failures or oscillating edits are no-progress signals; the run stops and names the smallest next action. The September 8 reassessment rule (#2858) went away with the tester.

The reviewer never sees the author's reasoning, and its verdict and severities are suggestions. The assistant reads each cited location and accepts or rejects the finding with a reason. That includes rejecting a finding that calls an instruction unclear when the instruction fits its purpose. Accepted required findings get fixed in one batch, affected checks rerun, and a targeted closure checks just those IDs. Use the reviewer when the authoring context is long, when a change touches a decision rule, gate, write authority or safety behavior, or when someone asks for an isolated review. Otherwise the assistant reviews the candidate itself. The reviewer runs on GPT-6 Luna (#2992).

The description is the contract

Research, planning and review look for skills and subagents whose description names their phase. They decide from the description alone.

A helper subagent returns sources and suggestions. It writes nothing; the phase assigns the IDs and writes the artifact.

Name the phase and the trigger.
Say what goes in and what comes back.

Snack Evidence is invented. #2902 added this guidance to HVE Builder's extension reference. rpi-research, rpi-plan and rpi-review each look for extensions whose descriptions say they are used during that phase, then follow the description on when and how to use them. rpi-implement follows the plan and does not look for extensions. Matching a description makes an extension eligible, but it grants no tools and the phase still decides. A helper subagent declares agents: [] unless nested dispatch is intended.

Clients last checked September 10, 2026: Copilot CLI v1.0.83 and VS Code 1.137.0. The deck only shows these commands.

The commands match GitHub Docs and HVE's current marketplace. Registering a marketplace does not install its plugin. The registration tracks main, so to update run copilot plugin marketplace update hve-core and then copilot plugin update hve-core@hve-core. #3113 documented this: the release/prerelease and release/stable refs no longer resolve, and a tag ref stays fixed at that tag. Remove that registration with copilot plugin marketplace remove hve-core --force and add microsoft/hve-core again. Copilot CLI cannot yet run manual-only skills such as git-commit (github/copilot-cli#4438). A real installation also needs supported clients, repository access and any trust approval.
