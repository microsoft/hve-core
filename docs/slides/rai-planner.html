SUMMARYContinues unless you object.

Prohibited uses are screened before the risk indicators. A match pauses the session.

You don't need to drive every phase manually. The planner summarizes Phases 1, 4 and 5 and continues unless you object. Phases 2, 3 and 6 are hard gates: you confirm the depth, mapping scope and final handoff. The prohibited uses check runs before risk indicators and pauses for explicit acknowledgment if a listed use applies. With the default profile, zero activated indicators suggests basic, one suggests standard, and two or more suggests comprehensive. You still confirm the tier. These are instructions the agent follows, not enforced permissions, so review what it does. The phases map to NIST Govern, Map, Measure and Manage; the source has the detailed mapping.

WORKED EXAMPLE / SCRIPTED

Use hve-builder for the repeatable parts

Contoso and its policies are fictional, but SR 26-2 is real. The Federal Reserve, FDIC and OCC issued this revised model risk guidance on April 17, 2026, replacing SR 11-7, and RAI Planner doesn't include it. That makes it a good test of the extension path. Read the scope before you add guidance like this. It isn't an enforceable standard, it's expected to matter most for banking organizations with more than $30 billion in assets, and it excludes generative and agentic AI. It fits Contoso's loan eligibility model, but it wouldn't cover the chatbot from the first example. Run the request in an authoring agent that can edit .github; RAI Planner itself only writes assessment artifacts. hve-builder reads the planner's extension points, summarizes the official text in its own words and links back to it. I'd still have someone from the model-risk team check that summary before the planner relies on it. The review catches a draft that replaces NIST even though the request says to layer the policies. The fix keeps NIST as the baseline, which is the extension pattern rai-standards describes. In the plan, SR 26-2 adds model risk checks under the NIST characteristics, and Phase 5 records the evidence for each gap. The agent running HVE Builder verifies findings and owns the fixes. A source review and lint pass aren't evidence that the extension works in a real session, so test it with representative assessments before you adopt it. Plugin installations may prefix the command, for example /hve-core:hve-builder. The file contents, finding, state and plan excerpt are illustrations, not executed results.
